# Text-to-SQL PoC 요구사항 정의서

작성일: 2026-11-02 / 작성: 성예찬 / 상태: 초안 (김다미 선임 확인 전)

## 1. 배경과 목적

- 상품시스템(PF) DB는 ERD가 복잡하고 일반 관계형이 아닌 **EAV(범용 메타 모델)** 구조라 직접 쿼리를 작성하기 어렵다.
- 자연어 질문을 SQL로 변환해 주는 Text-to-SQL로 이 부담을 줄인다.
- 이번 PoC는 **자연어 질문 → 순수 SQL 문 생성**까지가 목표다. SQL 실행과 결과 답변은 범위 밖이다.
- 11/13까지 각자 개인 챗봇 환경에 구현하고, 이후 메타데이터와 구현 내용을 취합해 본 서비스(InnoSolve) 연동을 검토한다.

## 2. 범위

| 구분 | 내용 |
|---|---|
| 포함 | 핵심 대상 테이블 OBJ_MAIN, OBJ_INV, OBJ_DETAIL에 대한 조회 SQL 생성 |
| 포함 | 패턴 데이터 관련 테이블: OBJ1800(가변패턴그룹), OBJ1810(패턴그룹별 유형), OBJ1000(유형, POOL_KBN=0이 패턴), 항목 정의용 OBJ1110·OBJ1200 |
| 포함 | 메타데이터(스키마·용어) 정의 및 관리 구조 |
| 포함 | 생성 SQL의 검증, 정답 SQL 기준 정확도 평가 |
| 제외 | SQL 실행 후 자연어 답변 (B안) |
| 제외 | 판가 조회(OBJ_DETAIL_REL → OBJREL_INC → OBJRELINC_PROP) |
| 제외 | 부서별 권한 연동, 화면(UI) 연동 |

## 4. 요구사항

### 4.1 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-01 | 사용자가 자연어로 질문하면 해당 정보를 조회하는 SQL을 반환한다 | 필수 |
| FR-02 | 메타데이터(테이블·컬럼 의미, 유효조건, 용어 사전)를 파일로 관리하고, 코드 수정 없이 교체할 수 있다 | 필수 |
| FR-03 | OBJ_MAIN 단건 조회 질문(코드 또는 이름)을 지원한다 | 필수 |
| FR-04 | OBJ_MAIN 유형별 목록·이름 검색 질문을 지원한다 | 필수 |
| FR-05 | OBJ_INV 기반 상·하위 구성 조회(하위/상위, 기본/서비스뷰 관계)를 지원한다 | 필수 |
| FR-06 | 지원하지 않는 질문은 "지원하지 않는 질문"으로 응답하고 이유를 알려준다 | 필수 |
| FR-07 | 모든 SQL에 최신 버전 조건(`END_DT = '99991231'`)이 사용 테이블 전부에 구조적으로 포함된다 | 필수 |
| FR-08 | 질문에 기준일자가 있으면 적용기간 조건(`기준일자 BETWEEN VF_DT AND VT_DT`)을 추가한다. 없으면 최신 버전만 조회한다 | 권장 |
| FR-09 | 질문 + 정답 SQL 30개 내외로 정확도를 측정하는 평가 기능 | 권장 |
| FR-10 | 메타데이터 출처를 구글 스프레드시트 등으로 교체할 수 있는 구조 | 권장 |
| FR-11 | 룰빌더 형식(기준일자 바인딩, 한글 별칭) 출력 | 선택 |
| FR-12 | OBJ_DETAIL 속성 조회: 한글 항목명(예: 약정기간)을 물리 컬럼(CHARnn)으로 변환해 값을 조회한다 | 필수 |
| FR-13 | 패턴 데이터 조회: 오브젝트의 패턴(KIND=패턴 TYPEID) 행을 항목명 별칭과 함께 조회한다 | 필수 |
| FR-14 | 패턴 구성 조회: 패턴그룹·적용유형·소속 패턴 목록을 조회한다 | 권장 |
| FR-15 | 항목 사전(항목명 ↔ 유형 ↔ 물리 컬럼)을 메타데이터로 관리하고, 이후 OBJ1110·OBJ1200에서 자동 생성할 수 있는 구조 | 필수 |
| FR-16 | 현장마다 다른 TYPEID·항목 컬럼 값은 코드가 아니라 **사이트 프로필**로 분리한다. 설정값 하나로 프로필을 교체하고, 프로필에 없는 유형·항목은 거절한다 | 필수 |

### 4.2 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-01 | **안전성**: 생성되는 SQL은 SELECT 한 문장만 허용한다. DML·DDL·주석·다중 문장은 차단한다 |
| NFR-02 | **인젝션 방어**: 사용자 입력은 형식 검증 후 바인드 변수로만 SQL에 들어간다. 프롬프트 인젝션으로 임의 SQL이 만들어지지 않는다 |
| NFR-03 | **결과 건수 제한**: 모든 SQL에 최대 행 수 제한을 둔다 (기본 100) |
| NFR-04 | **추적성**: 모든 요청은 requestId로 추적 가능하고 에러는 삼키지 않는다 |
| NFR-05 | **LLM 교체 가능**: 로컬 LLM(Ollama) 기본, 인터페이스 분리로 OpenAI 등으로 교체 가능 |
| NFR-06 | **DB 방언**: PostgreSQL 기본, Oracle도 지원한다. 방언은 메타데이터 설정으로 전환한다 |
| NFR-07 | **재현성**: LLM 없이 가짜 구현으로 테스트할 수 있다 (서버·GPU 불필요) |
| NFR-08 | **품질 게이트**: pytest, mypy(strict), ruff 모두 통과 |

## 5. 제약과 가정

- 본사 데모 환경 서버가 내려가 있어(11/2 기준) 실제 DB 접속이 불가하다. 로컬 **PostgreSQL 샘플 DB**로 개발·검증한다.
- 사용자는 개발자와 현장 인력이다. 결과 해석 답변은 필요 없고, SQL과 함께 "어떻게 해석했는지"(의도)를 보여주면 충분하다.
- TYPEID 값은 사이트마다 다르다. 현재 값은 샘플이며 서버 복구 후 교체한다.
- 구현 언어는 Python/FastAPI(코어·API), 화면은 이후 TypeScript. 개인 학습 목적상 구현은 본인이 직접 한다.
- LLM은 로컬 방향이며 모델은 미확정이다.

## 6. 확정 사항과 남은 확인 사항

### 6.1 확정 (2026-11-02, 성예찬 답변)

| 항목 | 결정 |
|---|---|
| 범위 | **A안(SQL만 제공)**. 솔루션 본부 사용자는 모두 개발자 수준 |
| 사용자 | 개발자 및 현장 인력 |
| DB | **PostgreSQL 기준**으로 진행. Oracle도 지원(방언 전환) |
| `END_DT` | 데이터의 **버전 종료일**. 새 버전이 생기면 이전 버전의 END_DT가 닫히고 새 버전 시작일자부터 새 행이 시작된다. 새 버전이 생기기 전까지 최신 버전은 `99991231` 유지 |
| OBJ_INV | SID = 상위, SUBSID = 하위 |
| LLM | 로컬 모델로 진행 예정 (모델 미정) |
| 역할 분담 | 각자 자기 프로젝트에서 진행. 11/13 이후 취합 |

### 6.2 ERD 근거로 확정한 해석 (서버 복구 후 실데이터로 재검증)

| 항목 | 해석 | ERD 근거 |
|---|---|---|
| OBJ_DETAIL.KIND | 1 = 오브젝트 기본 속성, 그 외 = 패턴 TYPEID | OBJ_DETAIL PK에 KIND, OBJ1810.KIND가 유형 ID(FK) |
| 패턴 항목 정의 | 패턴 TYPEID → OBJ1110(TYPEID, ITEMID) → OBJ1200(DISP_NAME, PHY_COLUMN1) | OBJ1110 → OBJ1200 FK 관계 |
| 다중값 속성 | 이번 PoC 제외 | 값이 OBJ_DETAIL_REL → OBJ_REL(MULTIID) 경유로 별도 저장되어 단순 조인으로 해결 불가 |
| OBJ_DETAIL 유효조건 | OBJ_MAIN·OBJ_INV와 동일하게 END_DT 조건 적용 | OBJ_DETAIL도 VF_DT, VT_DT, END_DT 보유 |

### 6.3 남은 확인 사항

1. **VF_DT/VT_DT의 정확한 의미**: 버전 시작·종료인지, 판매 등 적용기간인지. 과거 시점(기준일자) 조회 시 버전 선택을 END_DT로 하는지 VF_DT~VT_DT로 하는지. PoC 기본은 최신 버전만 조회하고, 기준일자는 질문에 있을 때만 적용기간 조건으로 추가한다.
2. 로컬 모델 종류와 실행 사양(GPU 유무). 미정이면 Ollama의 Qwen 계열로 시작한다.
3. 서버 복구 후 실제 DB에서 TYPEID와 표준항목 컬럼 매핑 값 확정.

## 7. 성공 기준

- 평가 세트 기준 실행 결과 정확도 측정이 가능하다.
- 템플릿 밖 질문은 안전하게 거절된다.
- 메타데이터를 교체하면 다른 사이트(TYPEID 상이)에도 코드 수정 없이 동작한다.
- 11/13에 취합 가능한 형태(메타데이터 파일 + 구현 설명)로 제출한다.
